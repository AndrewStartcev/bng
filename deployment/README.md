# Перенос BNG: два домена, одна установка WordPress

Цель: `bng-elements.ru` — русский, `bng-elements.com` — английский. Один каталог файлов и одна база данных; редактирование ACF остаётся общим, с существующими RU/EN полями.

## Перед переносом

1. Сохранить полный архив сайта (включая uploads, plugins, скрытые файлы) и SQL-дамп. В них есть конфиденциальные настройки и хеши паролей: не помещать в GitHub или публичную папку сайта.
2. На новом хостинге создать БД и каталог сайта. Подключить к этому каталогу оба домена и их www-алиасы. Не создавать вторую установку WordPress.
3. Восстановить файлы и SQL. Указать новые реквизиты БД в wp-config.php. Сохранить текущие пользователей и ACF-данные: исходные JSON в репозитории не заменяют актуальную БД.
4. Установить подготовленную тему. Новое видео `bng-trench-work-muted.mp4` подключается через поля главной `bng_home_video_ru` и `bng_home_video_en`.

## Конфигурация доменов

Скопировать domain-config.php из этой папки в непубличный каталог или корень WordPress и подключить в wp-config.php **до** строки загрузки wp-settings.php:

```php
require_once __DIR__ . '/bng-domain-config.php';
```

Имя файла при копировании должно соответствовать строке require_once. Удалить прежние определения WP_HOME/WP_SITEURL, если они есть. Файл использует строгий список четырёх разрешённых имён, не принимает произвольный Host.

Оба домена должны иметь HTTPS. SSL и привязки доменов настраиваются в панели хостинга. www приводится к основному имени через canonical WordPress либо редирект хостинга. Не настраивать постоянный редирект .com на .ru.

В базе заменить старый dev-адрес на `https://bng-elements.ru` инструментом с поддержкой PHP-сериализации, например WP-CLI `search-replace` с предварительным `--dry-run`, исключая GUID. Не делать обычную SQL-замену сериализованных ACF/WordPress значений. На .com абсолютные ссылки медиа на .ru допустимы: это та же установка и общий uploads.

Полностраничный кэш и CDN обязаны разделять ответы по Host. На первом запуске отключить кэш и проверить оба языка. Cookies входа остаются отдельными для каждого домена — вход в админку на .ru не авторизует .com автоматически.

## Проверка до DNS

Через локальный hosts или предпросмотр хостинга проверить оба домена с правильным Host и SSL. Проверить восемь разделов, PDF, картинки, видео, ACF и вход редактора. Переключатель языка должен менять домен и сохранять раздел через #fragment. На dev-хосте переключение остаётся внутри страницы.

Видео должно иметь только видеодорожку, атрибуты autoplay/loop/muted/playsinline и запускаться без клика. Некоторые браузеры в режиме энергосбережения могут запрещать автозапуск даже без звука.

## Переключение

После отдельного согласования обновить только DNS-записи сайта, сохранив MX/TXT и почтовые настройки. Дождаться распространения DNS, повторить проверки и сохранить старый dev-сайт и резервные копии для отката. При любых правках контента после экспорта перед окончательным переносом потребуется свежий SQL-дамп и новые uploads.
